# Qualification baseline

These files preserve product decisions and unresolved proof obligations before runtime
implementation. Their status qualifies the statement in that row, not an operational
capability:

- `verified`: the statement is an approved scope or architecture decision;
- `assumed`: an explicit hypothesis still requiring external evidence;
- `rejected`: behavior deliberately excluded or forbidden;
- `unresolved`: a question or acceptance claim not yet proven.

Browser and provider rows remain `unresolved` until their exact version, edition,
permissions, environment, and real acceptance suite are recorded. A provider family
name is never evidence of support.
