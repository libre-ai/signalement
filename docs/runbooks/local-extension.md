# Run the experimental local extension

This is a development build, not a browser-store release or a claim of browser parity.
Chrome, Firefox and Safari qualification is recorded separately in
`tools/browser-check/README.md` and `apps/extension-shared/video.README.md`.
No ticketing destination, server upload or reproduction worker is implemented here.

## Build and inspect

Use the repository's pinned Bun toolchain:

```sh
bun install --frozen-lockfile
bun run check
bun run build:extensions
```

The outputs are `dist/extensions/chrome`, `dist/extensions/firefox` and
`dist/extensions/safari`. Each directory includes the manifest, executable assets,
license notices and a SHA-256 build inventory. Output media and browser profiles are
never committed. For local trials, use only disposable profiles and synthetic pages.
Chrome's local unpacked-extension loader uses the Chrome output directory. Firefox's
temporary-addon loader uses the Firefox manifest. Loading a package is not evidence
that its complete capture, recording or storage workflow works.

## Local journey

1. Open a synthetic web page, then the extension. Opening it collects nothing.
2. Choose capture explicitly. Privileged pages, navigation races and revoked
   permission are refused. The editor receives a one-shot temporary capture.
3. Enter expected/observed behavior, application, environment and reproduction steps.
   Crop or apply opaque masks and check the actual derivative preview.
4. To record, explicitly choose a source. Audio is off by default. Produce a sanitized
   derivative and review the entire result; audio inclusion needs its own confirmation.
   Video masks cover their rectangle throughout the clip. Remove the entire video or
   audio when that is insufficient. Automatic captions are not supplied; include an
   accessible written account in observed behavior.
5. To save locally, unlock with a passphrase of 12–1024 characters. There is no recovery
   if it is forgotten. Choose retention within seven days; one day is the default.
   Lock clears the editor and stops active capture, sanitation and playback.
6. Prepare the export, read its Markdown, manifest and derivative previews, then
   explicitly approve that snapshot. Re-preparing or editing requires a new approval.
   The ZIP contains no quarantined original.

Verify the actual downloaded ZIP independently:

```sh
bun tools/contracts/verify-export.ts /path/to/synthetic-dossier.zip
```

This verifies the local-export contract and byte integrity only. Review still needs
to identify sensitive material in pixels, sound and free text. Suspected vulnerabilities
and exposed secrets belong to the fleet private security channel, never this intake.

## Safari native packaging

On a host with Xcode, the following creates and compiles an unsigned local wrapper;
it does not activate the extension or change Safari security preferences:

```sh
xcrun safari-web-extension-converter dist/extensions/safari \
  --project-location dist/safari-native --app-name Signalement \
  --bundle-identifier fr.libre-ai.Signalement --macos-only \
  --copy-resources --no-open --no-prompt
xcodebuild -project dist/safari-native/Signalement/Signalement.xcodeproj \
  -scheme Signalement -configuration Debug \
  -derivedDataPath dist/safari-derived CODE_SIGNING_ALLOWED=NO build
```

The bundle identifier's case matches the wrapper generated by Apple's converter.
Use a new generated output location if an earlier project already exists. Native
compilation was observed, with a missing-icon warning; installed Safari execution
remains unqualified because remote automation is disabled on the inspected host.
Any test requiring host security changes needs its own explicit authorization.
