Règles :
- Lectures par `deps.readFile(path, limit)` : reçu `65_536` octets
  (`receipt.size_limit` du contrat), clés `262_144` (`keys.size_limit`) ; échec →
  `receipt.unreadable` / `keys.unreadable`. Clés : `parseKeySet` (Task 7), donc le
  fichier produit par `signalement keys`.
- Ordre : `api.verifyReceipt(bytes, keys)` ; `valid` exigé, puis
  `rawProjectionReceiptFailures(bytes)` vide (défense en profondeur ; sinon
  `receipt.contract`). Correspondance : `invalid` → `receipt.signature_invalid`,
  `unknown-key` → `receipt.unknown_key`, `unreadable` → `receipt.malformed`. Aucune autre
  vérification sur un reçu non `valid` (des faits non signés ne sont pas des faits).
- `PolicyReceiptError` de code `artifact.missing` au chargement → `component.missing`,
  code `1`.
- Rapport, code `0` seulement si aucune vérification n'est `fail` :
  `{ "ok", "verified", "scope": "signature-only" | "signature-and-export", "keyId",
  "keyStatus", "checks": { "signature", "export", "transmittedFiles", "withheldFiles",
  "rendering" }, "failures": [...] }`. Sans `--export` : les quatre dernières valent
  `{ "result": "unavailable", "reason": "export-not-provided" }` (avec `"label": "non
  recalculé"` pour `rendering`). Un `unavailable` n'est jamais rapporté comme `pass`.
- `run` ne construit aucun client HTTP et ne lit ni jeton ni serveur pour cette commande.

### Task 10: `verify-receipt` — recalcul du corps rendu

Voulu (design §5.5, registre §4.2) : avec le document de l'export, `projectionId` et
`rendered.mediaLinks`, recalculer `renderBody` et comparer au `rendered.bodyDigest`
signé. « Non recalculé » seulement quand la version du moteur manque (ou que l'export
n'est pas fourni ou invalide, puisque le document en vient).

**Files:**
- Create: `apps/cli/render-check.ts`, `apps/cli/render-check.test.ts`
- Modify: `apps/cli/verify-receipt.ts`

**Interfaces:**
- Consumes: `parseExportPayloadView`, `buildRenderInput`, `PlannedDestination`,
  `renderBody`, `RENDERER_VERSIONS`, `markerText`, `idempotencyKey` (L3) ; `ReceiptFacts` ;
  `canonicalJson`.
- Produces :

```ts
export function renderCheck(facts: ReceiptFacts, files: readonly ArchiveFile[] | null):
  | { result: "pass"; label: "recalculé" }
  | { result: "fail"; label: "recalculé"; failures: ["rendering.mismatch"] }
  | { result: "unavailable"; label: "non recalculé"; reason: "export-not-provided" | "export-invalid" | "renderer-version-unavailable" | "render-input-incomplete" };
```

Algorithme (non déterminé par la signature) :
1. `files === null` → `unavailable` (`export-not-provided` ou `export-invalid`).
2. `RENDERER_VERSIONS[facts.profileId] !== facts.rendered.rendererVersion` →
   `renderer-version-unavailable` (la CLI embarque une autre version du moteur).
3. `payload = parseExportPayloadView(manifest.json)` ; destination planifiée reconstruite
   du reçu : `transmitted` → `transmit`, `withheld` → `withhold` + motif,
   `media = rendered.mediaLinks.length > 0 ? "link" : "withhold"` ; options :
   `kind = operation`, `marker` = marqueur de L3 pour
   `markerText(projectionId, idempotencyKey(projectionId, exportDigest, mappingVersion))`
   avec `within = null` (`create`) ou la référence de `remote` (`comment`),
   `linkedPaths` = chemins `via: "link"`, `mediaLinks` = `rendered.mediaLinks` en table
   chemin → URL, `attachedCount` = nombre de `via: "attachment"`.
   `input = buildRenderInput(payload, destination, options)`.
4. SHA-256 de `canonicalJson(renderBody(profileId, input).body)` comparé à
   `rendered.bodyDigest` → `pass` ou `fail`. Avant d'écrire, confirmer la sérialisation
   que L3 hache dans `buildUnsignedReceipt` (`grep -n "bodyDigest" packages/projection-core/*.ts`)
   et l'utiliser telle quelle.

Lacune connue (écart signalé au registre) : `RenderInput.revision` n'est pas dans le reçu
L1. Pour `operation: "create"`, la révision vaut celle de la première livraison (`1`,
à confirmer dans `executeDelivery` de L3) ; pour `operation: "comment"`, elle manque, et
deviner une révision produirait un faux `fail`. Tant que le contrat ne la porte pas, le
recalcul d'un reçu `comment` n'est pas tenté : `unavailable`, raison
`render-input-incomplete`, et le test qui l'affirme cite l'écart. Si L1 ajoute `revision`
avant l'exécution (`jq '.properties | keys'` du schéma vendorisé), cette raison et son
test disparaissent, remplacés par un cas `comment` recalculé.

Décision de l'agent ; publication = propriétaire.

| Canal | Forme | Vérification par l'utilisateur | Statut |

| B. *Choix de l'agent : WASM embarqué plutôt qu'adjacent, pour qu'un seul fichier porte le
code et la version exacte du composant ; pas de paquet de registre (surface en plus, sans
besoin mesuré).* Deux obstacles connus au canal B, à mesurer : (1) le chargeur L2 importe
sa glue par `import()` dynamique d'un chemin calculé depuis `import.meta.dir`
(`target/policy-receipt-wasm/generated`, plan L2) : un exécutable compilé n'embarque pas
un module chargé ainsi ; (2) le vérificateur vendorisé
`vendor/contracts/tools/quality/signalement-local-export-v1.ts:44-48` lit son schéma par
`Bun.file(new URL(..., import.meta.url))` au chargement, fichier octet-exact qui ne se
